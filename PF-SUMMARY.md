# PF Summary: Fuzzy URL dedupe

## What was built

Implemented configurable fuzzy result deduplication for `@vacinc/search-fusion`, enabled by default.

- Canonical URL identity now folds:
  - scheme and host casing
  - HTTP into HTTPS
  - default ports
  - trailing slashes and fragments
  - `www.`, `m.`, and `amp.` host variants
  - terminal `/amp`, `/amp/`, `/amp.html`, and `/amp/index.html` paths
  - default tracking parameters: `utm_*`, `fbclid`, `gclid`, `ref`, `mc_cid`, `mc_eid`, and `igshid`
- Meaningful query parameters remain in the identity. Parameter keys are sorted, while repeated-value order is preserved because it can be meaningful.
- Same-host normalized-title equality is a secondary dedupe signal. It is limited to HTTP(S), the same canonical host and port, and the same remaining meaningful query.
- Merge groups retain the highest-ranked result instance for title/URL identity, union provider provenance and variants, preserve the longest informative snippet, and keep existing ranking behavior.
- Evidence citation support resolves every merged variant URL back to its final merged row.
- The configured tracking policy now reaches provider result and answer-citation normalization before any irreversible legacy stripping. In override mode, parameters that become meaningful remain in display/navigation URLs and cite the correct distinct evidence row.
- New plugin configuration:
  - `fuzzyDedupe` (`boolean`, default `true`)
  - `trackingParams` (`string[]`, supports terminal `*` prefix patterns)
  - `trackingParamMode` (`"extend"` by default or `"override"`)
- `fuzzyDedupe: false` preserves the previous exact canonical-URL merge behavior.

## Known gaps and risks

- The required `www.`/mobile/AMP folding is intentionally heuristic. A site that treats one of those variants as distinct can opt out with `fuzzyDedupe: false`.
- Same-host pages with identical normalized titles and identical remaining queries can merge even if their paths differ. Cross-host, cross-port, and conflicting-query matches are explicitly blocked.
- Some sites use nominal tracking keys such as `ref` for meaningful routing. `trackingParamMode: "override"` now preserves those keys consistently in identity, navigation, and evidence attribution when they are omitted from the replacement list.
- Verification used deterministic provider-runtime fixtures and plugin-inspector runtime mocks; no live third-party provider APIs were called.
- The dependency vulnerabilities reported by npm were pre-existing dependency-tree findings and were not changed with an automated audit fix.

## Suggested follow-ups

- Include this behavior in the intended 0.3.x release/versioning pass when publish work is authorized.
- If real-world false-positive telemetry becomes available, add only demonstrated site-specific exceptions rather than broadening the default heuristic set.
